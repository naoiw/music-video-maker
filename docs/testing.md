# テスト・検証（#23）

## 実行方法

Node.js は .node-version、パッケージマネージャーは pnpm、Rust は stable、FFmpeg/FFprobe は PATH または実行ファイルと同じフォルダに配置する。FFmpeg 結合テストには libmp3lame、libx264、AAC、libopus、libvpx-vp9、libwebp、libwebp_anim、音声フィルタ、lavfi が必要。

リポジトリルートで実行する。

```powershell
pnpm install --frozen-lockfile
pnpm run build
pnpm test
cargo fmt --manifest-path src-tauri/Cargo.toml --all -- --check
cargo clippy --locked --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
cargo test --locked --manifest-path src-tauri/Cargo.toml
ffmpeg -version
ffprobe -version
cargo test --locked --manifest-path src-tauri/Cargo.toml -- --ignored --test-threads=1
```

コミット済みの pnpm-lock.yaml と src-tauri/Cargo.lock を使用する。Vite のビルド後に Rust テストを行う。CI も package.json の固定 pnpm と --frozen-lockfile、Cargo の --locked を使用し、終了時に両 lockfile に変更がないことを検証する。

## CI とテスト対象

Windows CI ではフロントエンドの型チェック・単体テスト、Rust の整形・lint・単体テスト、FFmpeg 結合テスト、デスクトップ実行ファイル生成を順に実行する。FFmpeg が必要な Rust テストは理由付きの ignore を付ける。CI は FFmpeg/FFprobe を準備し、名前の接頭辞ではなく ignore を付けた全テストを直列実行する（動画生成等のロック競合を避ける）。ignore は任意の失敗を隠す目的で使用しない。

| 対象 | 主な検証 |
| --- | --- |
| フロントエンド | ドロップ分類、レイヤー座標・順序・入力検証、設定スキーマ・保存順序、プリセット、エラー案内・診断 |
| Rust 単体 | 出力設定81通り、引数の分離、FFprobe JSON検証、音声フィルタ範囲・順序、素材読み込み、設定ファイル、進捗・中断、I/Oエラー分類 |
| 音声結合 | ノイズ低減、周波数応答、ゲイン、ラウドネス、リミッター、原音・加工音・末尾試聴 |
| 動画結合 | PNG/JPEG/GIF、複数レイヤーの順序・透過、中央80%・ぼかし背景、GIF全配置および追加レイヤーのループ（ぼかし背景と前景の色変化を含む）、出力設定、加工音との尺・音量、中断・再試行、破損素材からの復帰、既存出力の保護 |
| 出力の独立検証 | 保存済みMP4をFFprobeで再取得し、H.264/AAC、映像寸法、FPS、yuv420p、映像・音声・コンテナの尺を確認 |

## テスト素材

外部楽曲や画像、配布制約のあるサンプルは使用しない。FFmpeg の lavfi でサイン波やノイズを合成し、Rust image クレートで単色画像・GIF等を生成する。JSONのメタデータもテスト内で生成する。破損素材は短い任意のバイト列で作る。各テストは専用の一時ディレクトリで動作し、終了後に破棄する。素材ファイルをリポジトリに保存する必要はない。

## Windows 実機確認（自動テストの対象外）

- デスクトップ起動、ファイルダイアログ・ドラッグ＆ドロップ、日本語パス、素材プレビュー
- 3種類の解像度、24/30/60 FPS、画像配置、実際の音楽での聴感と動画の尺
- 原音・加工音比較、フィルタ切替、再起動後の設定・プリセット復元
- 破損素材、アクセス権限、ディスク容量不足、FFmpeg未検出、エラー診断、再試行、中断
- YouTubeへの投稿・再生互換性、setup.bat / build.bat による初回導入・起動

自動テストはGUI操作、実際の楽曲の品質、全FFmpegバージョンでの互換性を保証しない。実機確認の結果は確認した環境・バージョンとともに記録する。既存の出力検証の許容差や音質テストの閾値は緩和しない。


## ローカルビルドと総合検証

CI は FFmpeg の固定 ZIP を上流から SHA-256 照合してテスト用に取得し、結合テストを実行する。setup.ps1 の構文を確認し、build.bat --no-pause で exe を生成する。exe や FFmpeg は Artifact として公開しない。クリーン Windows での環境構築・手動操作は [総合検証](mvp-validation.md) で確認する。

## 追加レイヤー（#30）

Rust単体テストで相対座標の変換・範囲、不透明度、合成順、FFmpeg引数のパス分離と音声マッピングを検証する。ignore付き結合テストでは合成PNGを用い、重なり順、元画像のアルファと不透明度の乗算、レイヤー外の背景、出力尺を確認する。フロントエンド単体テストで百分率の変換、座標の検証、3解像度のピクセル矩形、重なり順を確認する。既存のGIF結合テストでは、ループ指定なし・有限回・無限回のGIFをベースの3配置に加えて追加レイヤーとして生成し、元GIFの尺を超えた複数時点の画素と音声尺を検証する。Windows実機では追加・削除・順序・位置・サイズ・不透明度、無効値での生成抑止、キャンセル、生成中の編集禁止、非同期のベースプレビュー更新後のレイヤー保持を確認する。

## 音声入力形式・用途別ドロップ（#31 / #32）

単体テストでコンテナとコーデックの組み合わせ、音声尺の優先順位、ドロップ先と単一ファイル制約を確認する。FFmpeg 結合テストでは WAV / FLAC / AAC / M4A / 音声付き MP4 / WebM / MOV / MKV を生成し、原音・加工音試聴と MP4 出力、音声の長さ、動画由来の映像が混入しないことを確認する。Windows 実機では DPI・スクロール時のドロップ位置とエリアの強調を確認する。

映像入力の結合テストでは合成した MP4 / WebM / MOV / MKV をベースの動的ぼかし背景および追加レイヤーに使い、ループ後の画素、出力尺を確認する。静止画WebPの3種類の配置と非対応ストリームも検証する。Windows実機のプレビュー・ドロップ操作は別途確認する。

### #31・#32 最終検証

- メタデータに音声尺がない live WebM を音声素材とし、映像の尺ではなくデコードした音声の尺を利用することを確認する。
- 3秒のベースと異なる周期の2動画レイヤーを1.6秒の加工音に合成し、重なり順、各ループ周期、長い映像の切り詰めを確認する。音声は440 Hzの成分と不要な880/1320/1760 Hzの成分を数値評価する。
- 実際のアニメーションWebPの明示拒否、無音GIFプロキシのフレーム変化・サイズ・ループ、音声のみ／映像のみのMP4、形式偽装・破損素材と再試行を確認する。
- Windows実機のDPI・スクロール・素材選択・プレビュー再生は自動検証の対象外で、手動確認を別途行う。


## macOS / Linux（#39）

Windowsの既存CIを維持し、Ubuntu 24.04 x64、macOS 15 Apple Silicon / Intel のネイティブCIを追加する。各OSで同じフロントエンド・Rust・全FFmpeg結合テストを実行し、`bash -n`、`bash setup.sh --check`、`bash build.sh --skip-install`、固定lockfileを確認する。Linuxでは仮想ディスプレイ上でプロセス起動の簡易確認も実行する。OSのパッケージマネージャーからFFmpegを取得し、バイナリは配布・Artifact公開しない。

macOSのGUI起動・ダイアログ・ドラッグ＆ドロップ、Linuxの実デスクトップでの描画・操作、FFmpeg検出、設定保存、試聴と動画生成の手動確認は別途必要。CI成功だけで実機GUIが確認済みとはしない。

Ubuntu 24.04 の FFmpeg 6.1.1 では GIF の `-stream_loop` による可変フレーム遅延のループ時刻に差が出た。出力時は GIF のループ拡張だけを一時コピーで無限に正規化し、GIF demuxer の `-ignore_loop 0` を使用する。フレーム画像・遅延を変えないことを単体テストし、既存の9種のベース出力・3種の追加レイヤー結合テストと色・尺の判定条件を維持する。

macOS ARM64 / FFmpeg 9.0.2 で `-shortest` により音声終了後も映像が1秒以上残るケースを確認した。加工なしでは映像フィルタの末尾を音声尺で trim し、音声はEOFまで読み切る。加工ありは従来どおり中間PCMの実測尺で `-t` を指定する。出力尺の許容差0.2秒を維持し、単体テストで両経路の引数と合成後の trim を検証する。


## GPUエンコード（#40）

CPUのみのCIでも必須検証を実行する。単体テストで固定候補・引数生成・自動選択順序・非対応時のCPU選択・GPU失敗後1回の再試行・中断/IOエラー時の再試行禁止、フロントエンドの設定移行と品質表示を検証する。FFmpeg結合テストでは試験エンコード、利用可能性の検出、および意図的に対象外のエンコーダーを選んだ場合のCPU出力、自動選択時の実際の出力（利用可能なGPUまたはCPU）、一時ファイル削除を確認する。物理GPUを必須とせず、実機の画質・速度は別途確認する。既存の全結合テストと出力尺・コーデック・解像度・ピクセル形式の検証を緩和しない。

実機確認は同じ素材・解像度・FPS・品質段階でCPU/GPUをそれぞれ出力し、実際のエンコーダー、総所要秒数、出力容量、映像/音声尺、再生互換性、細部の画質を記録する。GPU使用時でも速くならない場合がある。GPUドライバ・FFmpegバージョンを併記する。GPU実機の画質・速度の比較結果は未記録。

## 音声解析（#33・#34）
FFTの単体テストは既知の周波数bin、-6.02dBの振幅変化、逆相ステレオ、無音・短い末尾を確認する。FFmpeg結合テストでは合成WAVの2秒全曲に-6dBを適用し、波形bin、ピーク、RMS、周波数binの差、フィルタなしの一致、素材保護を検証する。フロントエンドでは共通スケール、周波数軸、試聴位置、dB表示を検証する。実機では素材・フィルタ変更後の結果無効化、波形クリック、画面リサイズ、長曲の処理時間、実際の楽曲の見え方を確認する。実機GUI確認は未実施。

## オーディオビジュアライザー（#36）
色と素材パスの排他・FFmpeg引数の有限入力/音声map/キー処理を単体テストする。実FFmpeg結合テストで合成音源の4表示形式、加工あり、原音・加工音選択、MP4の尺、画像の一部が可視化されること、背景維持、生成用一時ファイル削除を検証する。無音からトーンへ変わる合成音源で音量メーターの時間同期と原音/加工音の差も確認する。フロントエンドではデフォルト配置・色とenum検証をテスト。実機では音楽との動きの同期、複数レイヤーの順序、透過・不透明度、縦/正方形、GPU利用時の再試行を確認する。実機GUIおよび長曲の処理時間/一時容量は未確認。
