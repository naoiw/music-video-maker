# システム構成

## 技術選定

- フロントエンド: TypeScript / HTML / CSS / Vite（フレームワークなしを初期選択）。
- デスクトップ: Tauri 2 / Rust。OS のファイル選択、処理実行、設定保存を担当。
- エンコード: FFmpeg / FFprobe のネイティブ実行。既存のコーデック・フィルタを利用する。
- ブラウザ版: 将来 FFmpeg.wasm などの実行バックエンドを検討する。Tauri の実行ファイルを Pages に置くだけでは動作しない。

## 責務

    GUI (src/)
       ↓ 型付きサービスインターフェース
    Desktop backend (Tauri IPC)
       ↓ 検証済み設定
    Rust (src-tauri/src/)
       ├─ media / probe
       ├─ audio / filter
       ├─ video / encode
       └─ ffmpeg / process

フロントエンドは Rust 固有 API の呼び出しをサービス層に集約する。ファイル参照はパス固定にせず、将来ブラウザの File/Blob を利用可能な境界を設ける。処理パラメータと UI 状態を分離する。

## 安全性

- シェルを介さず、引数配列で FFmpeg を実行する。
- フィルタは許可済み種類・数値範囲から構築し、任意コマンドを受け付けない。
- 出力先を入力ファイルと同一にせず、上書き確認を行う。
- 一時ファイルは専用作業ディレクトリに置き、中断時に回収する。
- Tauri の capability は必要最小限とし、リモートページにローカル権限を付与しない。
- 実際の楽曲はリポジトリや CI に送らない。

## FFmpeg 配布

開発中はインストール済み FFmpeg を使用できる構成とする。配布時はバージョン・ハッシュ・ビルド構成・コーデック・ライセンス・ソース提供条件を確認し、FFmpeg/FFprobe の同梱を #24 で確定する。自作コードの Apache-2.0 と第三者のライセンスは区別する。

## 検証

設定値・引数生成を単体テストし、合成したテスト素材を使った FFmpeg 結合テストでコーデック・尺・寸法を検証する。Windows の GUI 操作は実機で確認する。

## 音声フィルタ処理

[音声フィルタ処理基盤](audio-filters.md) に共通の型・パラメータ検証・適用順序・FFmpeg グラフ生成を定義する。試聴と動画出力はこの基盤を利用する方針とする（#17、#18）。
