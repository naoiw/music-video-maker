# システム構成

## 技術選定

- フロントエンド: TypeScript / HTML / CSS / Vite（フレームワークなしを初期選択）。
- デスクトップ: Tauri 2 / Rust。OS のファイル選択、処理実行、設定保存を担当。
- エンコード: FFmpeg / FFprobe のネイティブ実行。既存のコーデック・フィルタを利用する。

## 責務

    GUI (src/)
       ↓ 型付きサービスインターフェース
    Desktop backend (Tauri IPC)
       ↓ 検証済み設定
    Rust (src-tauri/src/)
       ├─ media / probe
       ├─ audio / filter
       ├─ video / encode
       ├─ ffmpeg / process
       └─ settings / local JSON

フロントエンドは Rust 固有 API の呼び出しをサービス層に集約する。ファイル参照と処理パラメータはサービス層の型で扱う。処理パラメータと UI 状態を分離する。

## 安全性

- シェルを介さず、引数配列で FFmpeg を実行する。
- フィルタは許可済み種類・数値範囲から構築し、任意コマンドを受け付けない。
- 出力先を入力ファイルと同一にせず、上書き確認を行う。
- 一時ファイルは専用作業ディレクトリに置き、中断時に回収する。
- Tauri の capability は必要最小限とし、リモートページにローカル権限を付与しない。
- 実際の楽曲はリポジトリや CI に送らない。

## FFmpeg の利用

利用者が別途インストールした FFmpeg/FFprobe を外部プロセスとして使用する。ソースコードのみを公開し、実行ファイル・FFmpeg の同梱配布は行わない。検出・起動の詳細は [FFmpeg / FFprobe](ffmpeg.md) を参照。

## 検証

設定値・引数生成を単体テストし、合成したテスト素材を使った FFmpeg 結合テストでコーデック・尺・寸法を検証する。各OSの GUI 操作は実機で確認する。

## 音声フィルタ処理

[音声フィルタ処理基盤](audio-filters.md) に共通の型・パラメータ検証・適用順序・FFmpeg グラフ生成を定義する。試聴と動画出力はこの基盤を利用する方針とする（#17、#18）。

## 設定の永続化（#20）

TypeScript のバージョン付き設定スキーマで出力・フィルタ設定を検証し、Tauri IPC 経由で Rust がアプリ専用設定ディレクトリの settings.json に保存する。サイズ上限は16 KiB、書き込みは一時ファイルからの置換。素材パスは保存しない。スキーマとGUIの復元仕様は [基本 UI](ui.md) を参照。

## フィルタプリセット（#21）

既存の設定スキーマから音声フィルタ項目だけを抽出し、名前付きの複数設定を presets.json（version: 1、64 KiB上限）に保存する。settings.json とは独立し、同じ Rust の固定パス・一時ファイル置換処理を利用する。適用時は既存のフィルタ更新と自動保存を再利用する。

## エラー処理（#22）

RustのI/O種別・メディア処理エラーを `[MVM:CODE] 詳細` 形式で分類し、既存の文字列IPCを維持する。フロントエンドの共通エラー処理で操作別の案内と診断詳細に分離する。未知エラーにはフォールバックし、ENCODE_CANCELLEDは従来どおり中断として扱う。診断情報はセッション内の表示に限定する。

## 画像合成（#64）

blurredモードはRust imageクレートで同一素材を背景cover・ガウスぼかし・中央前景に合成する。合成PNGをプレビューIPCで返し、動画生成では保存先と同じファイルシステムに一時PNGを生成してループ入力する。前景・背景を毎フレーム再計算しない。contain/coverのFFmpeg処理は維持する。GIFだけはこの静止画経路をバイパスし、FFmpegのsplit/crop/scale/gblur/overlayで前景と背景を動的合成する。透過は黒に合成する。GIFプレビューは2枚のアニメーション画像のCSS近似表示（元のループ指定に従い、画素や再生同期は完全一致を保証しない）。

## 追加レイヤーの合成（#30）

既存の画像配置をベースとして保持し、encode_video IPC の任意引数 overlays で追加の画像レイヤーを指定できる。省略または空配列の場合は従来の単一素材経路を使用する。GUIでは layer-editor がインスタンス単位で選択・編集・順序を管理し、明示的なインターフェースを動画出力コンポーネントに渡す。services/layers.ts が座標変換・入力検証を担当し、components/visual-preview.ts がベース画像と追加レイヤーの選択・プレビューデコードを共通化する。ベースプレビューと追加レイヤーのDOMを分離し、非同期のぼかしプレビュー更新でも追加レイヤーを保持する。追加画像は WebView の object-fit: contain、相対位置・不透明度で表示し、出力のピクセル矩形に合わせる。GIF のプレビューは元のループ設定に従うため、出力と完全に一致するとは限らない。

- PNG/JPEG/GIF を最大8枚追加できる。配列の先頭から順に重ねる。
- x/y/width/height は出力キャンバスを 10000 とする整数の相対座標・サイズ（左上原点）。矩形はキャンバス内、幅・高さは正。矩形内でアスペクト比を維持して中央に配置する。
- opacity は整数の不透明度 0～100。素材のアルファ値に乗算する。
- Rustでパラメータと各ファイルを再検証する。FFmpeg のグラフは検証済み数値から構築し、パスは入力引数に分離する。
- ベースの静止画ぼかしは従来どおり一度だけ合成する。追加レイヤーは FFmpeg の overlay で合成し、GIFのループを強制する。音声入力のマッピング・中断・出力検証は従来経路を使用する。

## 動画生成モジュール

- `video.rs`: 出力設定・レイヤー設定の検証、前処理、エンコード実行・進捗・中断・保存の制御。
- `video/arguments.rs`: FFmpeg の入力引数・フィルタグラフ・ストリームマッピング・出力引数生成。
- `video/output.rs`: 保存先と FFprobe の出力結果の検証。
- `video/tests.rs`: 従来の単体・FFmpeg 結合テスト。

音声入力は audio::AUDIO_FORMATS を FFprobe・試聴・音声加工・動画生成で共用し、最初の音声ストリームを明示的にマッピングする。映像入力は `visual::inspect_visual` でエンコード時に再検証し、`load_visual` では動画を最大8秒の小さな無音GIFに変換してIPCで渡す。元動画全体は転送しない。静止画WebPはFFmpegでPNGへデコードしてぼかし合成にも利用する。追加の動画入力は `-stream_loop -1` と `V:0`（添付画像を除外）で選択し、音声側は `a:0` を明示して出力する。用途別ドロップはネイティブ物理座標をOSの表示倍率でCSS座標に換算する。

## OS依存部分（#39）

FFmpegの実行ファイル探索はOSのEXE_SUFFIXを用い、Windowsのコンソール抑制のみ条件付きコンパイルする。設定保存先はTauriのapp_config_dirを利用し、OSごとの場所に保存する。ネイティブのTauri/WebViewとOSパッケージが異なるため、macOS/Linuxの環境構築・ビルド・起動はsetup.sh / build.sh / run.shに分離する。既存のIPCやFFmpeg合成処理は共有し、ネイティブのソースビルドのみを提供する。

GIFの出力では元ファイルを変更せず、GIFのループ拡張のみを無限ループに正規化した一時コピーを作る。画像データ・フレーム遅延・透過・描画方式を再エンコードせず、FFmpeg GIF demuxer のネイティブループを使用する。ベース・追加レイヤーともに同じ処理を行い、一時ファイルは生成終了・失敗・中断時に自動削除する。動画コンテナは従来どおり `-stream_loop -1` を使用する。

加工なしのエンコードは `-shortest` に依存せず、出力FPSに変換した映像のみを音声尺で trim する。音声入力はEOFまで処理するためメタデータの尺が短くても音声を黙って切り詰めない。映像・音声・入力尺が許容差を超える場合は保存しない。加工ありの中間PCMは従来どおり実測尺で `-t` を指定する。
